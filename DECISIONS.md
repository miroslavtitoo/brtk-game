# DECISIONS.md — Журнал архитектурных решений

---

### 2026-03-15 — Canvas 2D вместо WebGL

**Решение**: Использовать HTML5 Canvas 2D API, а не WebGL/PixiJS/Phaser.
**Обоснование**: Telegram WebView на многих устройствах плохо поддерживает WebGL. Canvas 2D гарантирует совместимость. Для простой 2D-игры с <100 сущностями производительности достаточно.
**Альтернативы**: PixiJS (отклонён — лишний размер бандла, WebGL-зависимость), Phaser (отклонён — слишком тяжёлый для TMA).

---

### 2026-03-15 — vite-plugin-singlefile для инлайнинга

**Решение**: Весь билд — один HTML-файл (~46 KB gzip ~14 KB).
**Обоснование**: Telegram Mini Apps загружаются через URL. Один файл = один запрос = быстрый старт. Нет CDN/хостинга для ассетов.
**Альтернативы**: Обычный Vite-билд с chunk splitting (отклонён — лишние запросы в TMA).

---

### 2026-03-15 — Fixed timestep (1/60) с аккумулятором

**Решение**: Физика и логика обновляются ровно 60 раз/с, рендер — каждый кадр.
**Обоснование**: Детерминированное поведение на любых устройствах. На слабых телефонах логика не замедляется, просто пропускаются кадры рендера.
**Альтернативы**: Variable timestep (отклонён — нестабильные столкновения, разное поведение на разных FPS).

---

### 2026-03-15 — Плавающий джойстик вместо D-pad / кнопок

**Решение**: Виртуальный джойстик появляется где нажал палец, с dead zone 8px и radius 50px.
**Обоснование**: Естественный контрол для мобилок, не закрывает экран фиксированными элементами. Работает и с мышью для десктопного тестирования.

---

### 2026-03-15 — 360 AoE для Нити Ариадны вместо дуги

**Решение**: Все 8 уровней Нити Ариадны бьют на 360 (изначально была дуга).
**Обоснование**: Дуга на тачскрине неудобна — направление меняется с задержкой, игрок не может точно целиться. 360 AoE проще и приятнее для мобильной игры.
**Альтернативы**: Дуга (изначальный план, отклонён после тестирования).

---

### 2026-03-16 — Круг-круг коллизии без spatial hash

**Решение**: Все коллизии — O(n²) перебор, круг vs круг.
**Обоснование**: При <100 сущностях на экране это не является узким местом. Добавление spatial hash усложнит код без ощутимого выигрыша.
**Пересмотреть**: Если количество сущностей вырастет до 300+.

---

### 2026-03-16 — Снаряды врагов: pendingProjectiles паттерн

**Решение**: RangedEnemy копит снаряды в `pendingProjectiles[]`, GameScene дренит их через `drainProjectiles()`.
**Обоснование**: Enemy не должен знать о других системах (UI, коллизии). GameScene владеет пулом снарядов и управляет их жизненным циклом.
**Альтернативы**: EventBus (отклонён — оверинжиниринг для текущего масштаба), прямое создание в GameScene (отклонён — Enemy не должен иметь ссылку на сцену).

---

### 2026-03-16 — Босс-шоковая волна через флаг, а не событие

**Решение**: Boss устанавливает `shockwaving = true` на один кадр, GameScene проверяет и наносит урон.
**Обоснование**: Простейший способ коммуникации без EventBus. Флаг сбрасывается в следующем кадре. Для одного типа события (шоковая волна) это достаточно.

---

### 2026-03-16 — Переименование героев (МИРЕЙ, СВОРИОН, АРМЕТЕЙ)

**Решение**: Убрали реальные имена игроков (Мирослав, Святослав, Артём) и мифологические имена (Тесей, Орион, Прометей). Заменили на уникальные игровые имена.
**Обоснование**: Оригинальные мифологические имена слишком узнаваемы и не создают уникальности. Новые имена — гибриды, отражающие личность + мифологию.
